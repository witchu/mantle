# Commands

This guide offers some basic information for the CLI's commands which are not yet documented
elsewhere. To view the API of each command, run `mantle help [SUBCOMMAND]`.

## Deploy

Deploy a Mantle project. For a detailed walkthrough, see the [Getting
Started](/docs/getting-started#deploy-your-first-project) guide.

### Skipping place files

Pass `--skip-place-files` to deploy everything except place files. Place files are not published, and
their previous versions are kept in the state file. This is useful when you only want to update
configuration, thumbnails, products, and other resources without publishing a new version of your
places.

```sh
mantle deploy --environment staging --skip-place-files
```

### Reconciling thumbnails

If a deployment is interrupted (for example by Roblox rate limits), the experience's thumbnails on
Roblox can drift from the state file. You may see extra or duplicate thumbnails, or deployments may
fail with `One or more of the provided thumbnail ids are not valid`.

Pass `--reconcile-thumbnails` to compare the thumbnail IDs on Roblox with the state file before
deploying:

- Thumbnails in the state file which no longer exist on Roblox are uploaded again, and the thumbnail
  order is set again.
- Thumbnails on Roblox which are not in the state file are reported.

Pass `--prune-thumbnails` to also delete thumbnails on Roblox which are not in the state file. This
implies `--reconcile-thumbnails`.

```sh
mantle deploy --environment staging --prune-thumbnails
```

<Callout type="warning">
  `--prune-thumbnails` deletes every thumbnail which Mantle does not track, including thumbnails
  uploaded manually through the Creator Dashboard.
</Callout>

you can run `mantle outputs` from your project directory.

## Destroying

If you want to destroy a deployment you can run `mantle destroy` from your project directory.

## Importing

Mantle provides an import feature so that you can deploy to an existing experience with Mantle.

<Callout type="warning">
  The import feature _**DOES NOT**_ convert your existing Roblox project into a
  Mantle project. Do not import, then deploy a place with Mantle without first
  testing on a staging environment as you may destroy your assets.
</Callout>

After creating a staging environment with Mantle that is on-par with your production environment,
you can import your production environment into Mantle so that you can deploy to it. This feature is
still experimental and does not do a good job of matching existing resources to configured ones so
most resources will be recreated.

Run `mantle import --environment <your-environment> --target-id <experience-id>`.
